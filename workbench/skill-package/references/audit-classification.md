# 设计工具箱：走查分类与证据规则（本项目自定义）

本规则是工作台的产品约定。上游 Yangao 的像素算法和九个细分信号仅作为底层实现参考，不决定最终展示类型、优先级或是否成立。

## 三个独立问题

1. **能否比较**：先核对页面、状态、语言、内容、视口、像素密度、滚动位置和加载时机。输入不可比时停止；存疑时标记为辅助审查。
2. **差异是什么类型**：每个可见对象只选一个主类型，保留多个细分证据。主类型可以人工改正。
3. **是否值得处理、何时处理**：确认状态、影响程度和 P0–P3 优先级由审查者分别决定，不从像素面积自动推导。

## 判定顺序

1. **先校准输入**：确认设计/实现角色、原图尺寸和导出倍率。只有导出倍率不同时才按宽度等比例归一；不同响应式视口保留原像素、比较共同区域。不得把两图独立拉伸到同宽同高。必要时用用户确认的对应元素做平移对齐，不从元素框推断缩放。
2. **再核对可比性和存在性**：先查同一页面、状态、滚动位置及媒体/文案是否应一致。一侧空白、一侧有卡片时，先提出内容/状态核对；没有两侧外框就不计算卡片尺寸、字体或圆角。
3. **最后分解可见组件**：用匹配的外框量位置、尺寸和相邻间距；用同一可比表面检查颜色/材质；用独立边界检查描边、圆角和选中态。变化的照片、时间、文案不得遮蔽仍然稳定的组件外框，也不能反过来充当外框证据。

若一处全局位移使多个局部相对间距一起变化，优先解释共同锚点的位移，不把每个子元素都报成独立缺陷。若局部间距确实独立变化，记录相邻元素及其两侧距离，而不是仅报告像素重心不同。

## 主类型

| 类型 | 可以这样判断 | 不应这样判断 |
| --- | --- | --- |
| 位置 | 双侧匹配的组件外框或锚点整体偏移、相邻组件间距不同 | 用不同文本或照片的像素重心推断组件移动 |
| 尺寸 | 双侧匹配的外框宽高不同 | 用字形宽度或图片纹理差异推断容器尺寸 |
| 颜色 | 同一可比表面的填充、文字或描边颜色有稳定差异；整页底色合并为一条 | 把不同照片的平均颜色当作 UI 色值错误 |
| 样式 | 同一组件的边框、圆角、阴影、透明度、填充方式或选中态处理不同 | 只见一小段纹理就推断整组件圆角或阴影 |
| 文字 | 文案已确认相同，且可见排版、字重、行高等有差异 | 未做文字内容核对就声称精确字号或字体名 |
| 图标 | 图标身份和区域可对应，外轮廓或颜色不同 | 把孤立像素片段命名为完整图标 |
| 布局 | 多个已对应组件的相对顺序、对齐或分组关系不同 | 把整块媒体内容变化称为布局错误 |
| 内容 | 一侧明显有内容而另一侧为空，或两侧素材/数据不同；默认是状态核对问题 | 未确认业务状态前称其为开发缺陷 |

如果同一视觉修饰同时给出颜色和边框信号，只创建一条记录：主类型按可见的组件问题选择，细分信号留在证据里。不同修复维度（如整栏位置、背景呈现和内部选中态）可分开记录。顶部状态标签的底色属于“颜色”；底部导航整块选中填充属于“样式”；卡片外框大小近似一致而整体位移属于“位置”。底部操作栏在双侧具有可匹配的上、下长外框、高度近似一致但底部留白不同，也属于“位置”。这些是当前截图回归的明确案例，不是对任意页面语义的保证。

底部操作栏的中性背景区域若一侧有稳定的纵向明暗过渡、另一侧近乎均一，可另提“背景质感”样式候选；选中态填充是栏内的另一个子控件，不应被背景候选吞并。静态截图只能证明最终可见的明暗与纹理差异，不能单独证明使用了半透明、`backdrop-filter`，或某个具体模糊半径。两侧媒体素材不同造成的背景变化仍需人工复核。

## 证据门槛

- 对位置、尺寸、布局：必须有双侧可对应的稳定边界或锚点。单侧轮廓只允许提出“内容/状态待核对”。
- 底部留白测量只适用于两张同宽、完整且纵向对齐的截图；输出为**截图像素**，不能直接称作 CSS 像素或安全区实现值。外框高度变化明显、截图裁切不同、或无法稳定找到双侧外框时，不自动报“底部位置”。
- 对颜色：比较同一表面，先排除全局底色偏移、透明叠层、图片纹理和动态内容。
- 对样式：观察完整或足够稳定的组件边界。边框、圆角、阴影必须各有独立证据；不能从平均颜色推导。
- 对文字和图标：像素启发式不等于 OCR 或语义识别；不能确定身份时使用中性描述或不输出。
- 对动态时间、文案、图片：先作为输入状态差异处理；保持真实的外框与前景组件仍可继续审查。
- 对顶部在线状态标签：先扣除页面整体底色差，再比较标签本身的填充和描边。整体背景变色不能自动解释为标签变色。
- 对卡片：媒体素材、卡片是否存在、外框位置、描边属于不同证据；图片纹理不等于卡片边框。设计稿无描边而实现有描边时，可报告样式候选，但不要从局部线段推断全卡片圆角。
- 对底部栏：外框距底边、栏背景的可见明暗/透出、内部选中态填充和外框圆角分别取证。背景候选不得因为包含内部选中态而把后者去重；静态截图不能证明具体透明度、模糊半径或 CSS 属性。
- 不设通用“超过 1px 必报”的阈值。阈值要随缩放方式、对象大小、图像质量和证据类型变化。
- 机器结果统一称“候选问题”。审查者确认后才进入默认导出清单；分类可修改，但人工改类不自动确认问题。

## 数据约定

每条问题保存 `category`（稳定英文 ID）、`categorySource`（`auto` 或 `manual`）、`types`（底层细分信号）、审查状态、影响程度和优先级。列表、详情、Markdown、JSON 和标注 PNG 使用同一条问题的当前分类；分类筛选不得改变原始检测结果或影响处理状态。
