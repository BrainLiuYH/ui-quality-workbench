# 走查反馈案例库

这里记录用户在设计稿与实现截图对比中指出的漏报和误报。它是**回归需求与证据边界**，不是“用户说过就自动确认为开发缺陷”的标签集。只收录走查判断、输入可比性和结果审阅相关反馈；导入方式、页面美化、仓库发布等属于其他产品功能，不混入视觉判定规则。

`已覆盖`表示当前有相应实现和合成回归，**不表示泛化准确率已被证明**；`部分覆盖`表示某个可见子问题可提候选，但更精确的归因还不可靠；`待增强`表示不应声称自动识别。真实截图可用于本地复核，不把用户图片、路径或业务数据打包进可分发的 Skill。

下表中的 `workbench/tests/...` 是源码仓库里的回归文件定位；独立安装的 Skill 不附带测试源码。

## 新反馈如何进入规则

1. 记录设计/实现角色、原图宽高、页面与状态、视口/DPR、滚动位置、媒体和文案是否可比。角色或比例不明时先停在输入问题，不能用拉伸制造“匹配”。
2. 把用户指出的**可见现象**、可能的替代解释和当前证据等级分开写。截图中的明暗过渡可测；`backdrop-filter`、精确字号、真实安全区实现和缺失内容的业务原因不能仅凭截图证明。
3. 先查 [分类与证据规则](audit-classification.md) 是否已经覆盖。若需改检测器，使用组件关系和相对尺度，不写死某张图的坐标、文案、色值或候选数量。
4. 至少加入一个应命中的正例和一个不应命中的反例（相同截图、素材变化、整体平移、不同视口或相似但非同一组件按需选取）。检查旧候选是否被新候选吞并；在原始双图仍可用时再跑一次真实对比。
5. 分别观察漏报和误报。只有在可比的回归集合上二者都被评估后，才谈“准确率提升”；规则变多本身不能证明提升。人工改类、确认或驳回要保留为审查结果，不反向伪装成机器已学会。

## 已讨论的案例

| ID | 用户反馈与当前可见证据 | 判定规则 / 不能越过的边界 | 当前状态与回归 |
| --- | --- | --- | --- |
| F01 | 两图尺寸不一致时曾把元素大小和字号比错。 | 区分导出倍率与响应式视口；仅倍率不同才把较窄图按宽度等比放大，绝不独立拉伸宽高。相同宽度保留原尺度。 | 已覆盖：`workbench/tests/yangao-engine.test.mjs`、`workbench/tests/image-sources.test.mjs`。设备 DPR 仍需用户核对。 |
| F02 | 用户尚未走查时出现预置问题详情和列表。 | 结果只来自当前输入与本次走查；输入更换、对齐/比例改变后旧结果失效。无结果不应导出问题清单。 | 工作流已实现；仍需 UI 端到端回归。 |
| F03 | 不同时间、文案、模板图片让系统误判字号/元素尺寸，或整页被判不可比。 | 先判可比性；素材/数据变化可降低等级，但不能单凭纹理差异判低可比。内容差异优先中性描述；位置/尺寸必须有双侧外框。 | 已覆盖：`workbench/tests/comparability.test.mjs`、`workbench/tests/content-noise-integration.test.mjs`、`workbench/tests/classification-gates.test.mjs`。 |
| F04 | 草稿入口对不上，用户认为相邻元素间距有变化。 | 先区分整页/整卡位移与组件内部独立间距；必须匹配两侧锚点并量相邻距离，不能用字形或素材重心代替。 | 待增强：尚无稳定的“草稿入口间距”自动候选与正反例。 |
| F05 | 有卡片被认为不该有描边，另有页面出现设计稿有内容而实现为空白。 | “卡片描边样式”和“内容是否存在”是两类问题；只见一侧卡片时先问页面状态，不声称它的尺寸/圆角错误。媒体纹理不等于边框。 | 部分覆盖：`workbench/tests/classification-gates.test.mjs` 的描边与大面积存在性用例；卡片语义与业务状态需人工确认。 |
| F06 | 顶部在线状态标签的背景和描边与设计稿不同。 | 比较标签相对页面背景的填充/轮廓；不能把整页底色偏移当作标签自身改色。 | 部分覆盖：真实双图能提出局部颜色候选；还需独立的全局底色反例。 |
| F07 | 浅色会话卡片的纵向位置偏移，素材/文案也变化。 | 双侧浅色外框宽高近似相同而整体平移才报“位置”，不报“尺寸”；内容变化不应抹去外框证据。 | 已覆盖：`workbench/tests/classification-gates.test.mjs` 的卡片平移用例。 |
| F08 | 底部操作栏离底边的距离不同。 | 同宽同高、未裁切且可匹配上下长外框时，量**截图像素**中的底部留白；外框高度变化或对齐不可靠时不自动归为位置。不能把截图像素直接称作 CSS px。 | 已覆盖：`workbench/tests/classification-gates.test.mjs`、`workbench/tests/findings-adapter.test.mjs`；真实双图测得约 62px 对 107px。 |
| F09 | 设计稿底栏背景视觉上有半透明/模糊感，实现稿更像均一实色。 | 可报告稳定的栏内明暗/透出差异为“样式”候选；不同媒体可能影响效果，需人工复核。截图**不能证明**具体透明度、模糊半径或 CSS 属性。 | 已覆盖可见外观：`workbench/tests/classification-gates.test.mjs`、`workbench/tests/findings-adapter.test.mjs`；参数识别不支持。 |
| F10 | 底部栏外框圆角和选中态有差异。 | 外框轮廓、背景质感和内部选中态分开取证；重叠框不能让背景候选吞掉选中态。只凭一小段角部像素不报精确圆角半径。 | 部分覆盖：`workbench/tests/classification-gates.test.mjs` 的选中态并存和角部用例；精确半径待增强。 |
| F11 | 用户肉眼看到明显的字号/元素大小差异，但机器数值对不上。 | 文字内容、字体加载和设备尺度未校准时，不报精确字号或字体名；尺寸只量双侧匹配的组件外框。必要时建议源级样式/Figma 信息核验。 | 部分覆盖：误报被抑制；可靠 OCR/字体度量和组件尺寸归因仍待增强。 |
| F12 | 问题需要分成位置、颜色、样式等，并按优先级导出。 | 八个主类型与底层信号分离；严重程度、优先级、确认状态互不替代。默认只导出人工确认项；无结果不可导出。 | 分类已覆盖：`workbench/tests/finding-categories.test.mjs`、`workbench/tests/findings-adapter.test.mjs`；优先级仍由审查者决定。 |
| F13 | 页面大面积底色变化不应裂成许多小问题，也不应掩盖组件差异。 | 全局底色合并为一条颜色候选；后续组件分割要扣除均匀背景偏移。 | 已覆盖：`workbench/tests/classification-gates.test.mjs`。 |
