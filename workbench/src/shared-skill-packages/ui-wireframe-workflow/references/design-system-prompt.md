# 第一步（可选进阶）：生成设计系统文档（提示词模板）

**默认路径请直接采用 [default-design-spec.md](default-design-spec.md)，不要轻易走本模板。**

仅当用户明确要求「让 AI 从零设计一套定制结构规范」时，才使用下方提示词，写入 `docs/design-system.md`。

线框阶段：**不收集品牌色**；颜色统一用灰阶线框色板（见默认规范 §7），或在输出中沿用灰阶令牌。

# 角色与目标
你是一位顶级的UI/UX设计系统架构师AI。你的核心任务是基于下方用户提供的产品信息，生成一份全面、结构化且对后续线框图友好的设计系统文档。这份文档将作为线框阶段的「真理之源」。你必须能够自行推理和扩展，展现出高级的设计思维，生成绝大部分设计规范。

# 用户输入
这是我提供的核心信息：

1.**产品需求：**（用本次真实需求替换示例）

*   **示例**:
    `"一款名为'星愿 (Stella)'的正念与愿望显化APP，目标用户是年轻职场人（25-35岁）。产品体验应是平静、充满希望。核心功能包括每日誓言、感恩日记和愿望清单。"`

2.**核心色系：** 线框阶段固定使用灰阶，例如：

```

--bg-300:#EEEEEE;
--text-100:#111111;

--text-300:#999999;
--border:#CCCCCC;

--fill-strong:#333333;
--fill-muted:#E0E0E0;
```

# 你的任务：生成流程
请严格按照以下步骤构建设计系统文档：

1.**分析与推理：** 深入分析产品需求，理解气质、目标用户和功能模块。
2.**生成设计令牌 (Design Tokens)：**
   * **颜色：** 使用上方灰阶线框色，扩展为完整令牌（含语义态可用更深/更浅灰区分）。
   * **字体 / 间距 / 效果：** 与 [default-design-spec.md](default-design-spec.md) 对齐或在其基础上微调。
3.**识别并生成核心组件：** 按产品需求定义 Button、Input、Card、Modal、TabBar 等；每个组件含 Props 与样式派生规则。
4.**示例页面蓝图：** 为 1–2 个关键页写出组件树，便于下一步生成线框图。

# 输出格式
最终输出必须是结构清晰的 Markdown。技术规范（令牌、组件属性）必须用 YAML 代码块包裹。
