# UI Wireframe Workflow

把一个产品想法，按专业设计流程做成可在浏览器直接预览的**低保真产品原型线框图**。流程两段、一道确认门：

1. **设计系统文档**（Single Source of Truth；先问用户有无自有规范，没有再用内置默认）
2. **低保真线框图**（单文件 HTML）→ ⛔ 必须用户确认后才算完成

本 skill **只做到线框图确认为止**，不索取参考图、不提取风格 DNA、不生图抠图、不生成高保真 React 工程。若用户之后要做高保真，可再切换到 `ui-design-workflow`。

## 适用边界

- 产出设计系统文档 + 可预览的低保真线框图，覆盖页面、导航、组件占位、信息架构。
- 用真实感的简体中文文案 + mock 文案让结构可端到端审阅。
- 不做品牌配色定稿、不做真实后端、不做高保真视觉落地；除非用户明确扩大范围。

## 完成定义（Definition of Done）

以下全部为真前不得宣称完成：

- 已**先询问**用户是否有自己的设计规范，再决定用其规范还是内置默认；来源明确、未凭空编造。
- `docs/design-system.md` 存在，含设计令牌（字体/间距/圆角/图标/尺寸）与组件库；线框阶段使用灰阶色令牌（见默认规范），不收集品牌色。
- 低保真线框图已写入 `wireframes.html`，可直接在浏览器打开预览。
- 已向用户展示线框图并**请求确认**（页面是否齐全、信息架构与布局是否符合预期、有无增删）；用户提出修改则迭代直至确认。
- 每个手机画板 375×812、带手机边框、含 iOS 状态栏（9:41/信号/电池）、内容区独立滚动、底部 Tab 固定。
- 给用户清晰的预览说明（如何打开 `wireframes.html`）。

## 默认产出形态

除非用户另有要求：

- **设计系统**：`docs/design-system.md`
- **低保真线框图**：单文件 `wireframes.html`（Tailwind CDN + FontAwesome CDN）
- 手机画板 375×812，外包手机边框，含 iOS 状态栏，内容区独立滚动，底部 Tab 固定
- 视觉为黑白线框感（灰阶令牌），不追求品牌配色
- 简体中文优先

## 工作模式

有足够 brief 就自主推进，但**确认门不可跳过**：线框图必须经用户确认才算完成。其余只在「会实质改变产品」的缺失决策上提问。动手前先检查仓库，适配已有文档而不是覆盖重建。绝不暴露/回显/提交任何凭证。

## 工作流

复制此清单并跟踪进度：

```
进度：
- [ ] 0. 对话收集需求（目标用户 / 气质 / 核心功能；不收集品牌色）
- [ ] 1. 确立设计系统文档（用户给全套 或 用内置默认）docs/design-system.md
- [ ] 2. 生成低保真线框图 wireframes.html  →  ⛔ 用户确认门（本 skill 终点）
```

### 0. 对话收集需求

以**对话方式**向用户了解产品，**不收集品牌色**：

- 目标用户与气质基调、核心功能模块、主要页面 —— 缺失就直接问用户，问清再继续。
- **不要问配色 / 品牌色**：线框阶段统一用灰阶；品牌色留给后续高保真流程。

**设计规范：必须先问用户「有没有自己的设计规范」，没有再用默认**：

- **先明确询问**用户是否已有自己的设计规范 / 设计令牌（字体 / 间距 / 圆角 / 图标 / 尺寸等）。这一问不可省略。
- 用户有 → 直接全套采用其规范（线框色仍可用灰阶，除非用户规范已含色）。
- 用户没有 / 让你定 → **才用内置默认** [references/default-design-spec.md](references/default-design-spec.md)。
- 二选一，不给多选项菜单、也不让 AI 凭空发明一套；但「有没有自有规范」这一句必须先问。

### 1. 确立设计系统文档

把上一步选定的规范整理成 `docs/design-system.md`，作为线框图的唯一事实源：

- **用户给了完整规范** → 据此整理成结构化 Markdown（YAML 令牌 + 组件库）。
- **否则（默认路径）** → 直接采用 [references/default-design-spec.md](references/default-design-spec.md) 的全部令牌
  （画板/布局、字体、间距、圆角、图标、线框灰阶色、组件规则）写入 `docs/design-system.md`，并结合本次核心功能补一份
  组件库 / 示例页面蓝图。
- **不收集、不编造品牌色**；使用默认规范中的线框灰阶色令牌即可。

> 进阶（可选）：仅当用户明确要求「让 AI 从零设计一套定制结构规范」时，才参考
> [references/design-system-prompt.md](references/design-system-prompt.md) 的提示词模板；即便如此，颜色仍用灰阶线框色，不引入品牌色。

### 2. 生成低保真线框图 → ⛔ 确认门（终点）

阅读并使用 [references/wireframe-prompt.md](references/wireframe-prompt.md) 中的提示词，**严格且唯一地**
依据 `docs/design-system.md` 生成低保真黑白线框感的多界面 HTML 原型（所有 CSS 走 `:root` 的 CSS 变量；
375×812 画板 + iOS 状态栏 + 内容区独立滚动 + 底部 Tab 固定；网格横向排列，每行 3–4 屏）。
写入 `wireframes.html`。

**完成后停下，向用户展示并请求确认。** 明确询问：页面是否齐全、信息架构与布局是否符合预期、有无要增删的
页面或模块。用户提出修改则迭代线框图直至确认。

**确认后即交付完成。** 交付物：

- `docs/design-system.md`
- `wireframes.html`（说明用浏览器直接打开即可预览）
- 简要说明：本流程止于线框图；若需参考图配色 + 高保真 React，可继续使用 `ui-design-workflow`

## 不可妥协的规则

- 确认门不可跳过：线框图必须经用户确认才算完成。
- 设计规范：**必须先问用户有没有自己的规范**，有则全套采用，没有再用内置默认 [references/default-design-spec.md](references/default-design-spec.md)；不做选择题菜单、不凭空编造，但这一问不可省略。
- 不在本流程收集品牌色：线框用灰阶令牌；品牌视觉留给高保真流程。
- **本 skill 终点是线框图确认**，不自动进入参考图分析、生图、React 工程。
- 做移动端 App 线框，不是桌面营销页；手机边框只是展示外壳，画板内 375×812。
- 默认所有面向用户的文案为**简体中文**，除非用户明确要求其它语种。
- 主要移动控件点击区域不小于 44px；尊重安全区与内容溢出。
- 失败的动作绝不报告为成功；不跑完检查不宣称完成。
- 绝不暴露、回显或提交任何凭证。
- 不构建生产后端，除非用户明确扩大范围。
